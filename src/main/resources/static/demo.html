    Behind the answer

    A complete RAG pipeline

    Illustrative architecture

    A live assistant prepares documents once, then retrieves the most useful evidence for each question. Each step solves a different problem; skip one and answers can become harder to find, less reliable, or impossible to verify.

    01 Prepare knowledge · indexing happens when documents are added

    1. Upload & authorizeBrowser · Keycloak · workspace

      Checks who is uploading and which workspace they may use. This keeps one user's documents separate from another's.

    2. Keep the originalRustFS · S3

      Stores the source file durably, so it can be reprocessed and the answer can point back to the original document.

    3. Queue an indexing jobPostgreSQL · job status

      Tracks progress and failures outside the upload request. Large files can be processed reliably without making the browser wait.

    4. Extract readable contentSpring Boot · PDFBox · optional transcription

      Turns supported files into text. Audio transcription is used when enabled; retrieval needs text to search.

    5. Split into passagesUp to 1,500 characters · overlap

      Creates focused, manageable pieces while overlap preserves context across boundaries. Smaller passages make evidence easier to find.

    6. Embed each passageInfomaniak AI · embeddings

      Maps meaning to a numerical vector. Similar ideas can then match even when a question uses different wording.

    7. Save text & vectorsPostgreSQL · pgvector · full-text index

      Keeps passages, vectors, document references, and workspace ownership together for fast, scoped retrieval later.

    02 Find a grounded answer · repeated for each question

    1. Ask & check accessBrowser · Keycloak · OIDC

      Receives the question and verifies the signed-in user's workspace before searching private content.

    2. Embed the questionSame embedding model

      Converts the question into the same vector space as the passages, making semantic comparison possible.

    3. Retrieve candidatesHybrid search · pgvector + full text

      Combines meaning-based search with exact word matching. This helps find both paraphrases and important names or terms.

    4. Rerank for relevanceBAAI/bge-reranker-v2-m3

      Scores candidate passages against the full question and moves the strongest evidence to the top.

    5. Build focused contextBest-matching passages

      Selects a small set of relevant evidence for the model. Focus reduces distraction and keeps the prompt within its limits.

    6. Generate from evidenceInfomaniak AI · chat LLM

      Uses the question and retrieved context to draft a response. The current app abstains when retrieval returns no passages; if irrelevant passages are returned, it may still generate an answer.

    7. Return answer & sourcesPassages → browser

      Includes document and passage references so a person can check where the answer came from.

    What this demo does: this page uses fictional sample documents and prepared answers; it does not run these live AI or retrieval steps. The pipeline above explains the live application's architecture.

    Example configuration: model names below illustrate one setup. The private app displays its actual provider and model settings at runtime; retrieved sources are evidence to inspect, not proof that every answer is supported.
