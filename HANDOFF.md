# GenAI RAG MVP Handoff

## Current state

- IntelliJ-ready Maven project at this repository root: Java 27, Spring Boot 4.2.0, Spring AI 2.1.0, PostgreSQL/pgvector.
- Infomaniak AI Services chat and embeddings use the OpenAI-compatible API. Configuration is in `.env.example` and `deploy/k8s/`; account-specific API token, product ID, model IDs and embedding dimension must be supplied locally.
- The Compose stack is deployed on the Infomaniak VM using PostgreSQL/pgvector, RustFS, and the Spring Boot app. The database, API, S3 API, and RustFS console bind to loopback only; use an SSH tunnel to access them. Bucket initialization is automatic.
- Portainer CE 2.45.2 is included in Compose for container management, published on loopback port 9443 with persistent state. Its first-run administrator account must be created promptly after launch.
- The deployed `.env` selects `RAG_PROVIDER=offline` because no Infomaniak AI credentials were configured. The generated Compose credentials are in the ignored local `.env` (mode 600) and the remote `/home/ubuntu/genai-rag/.env` (mode 600); do not commit or print them.
- Keycloak/OIDC and workspace isolation are implemented locally but have not yet been deployed to the existing VM. Compose now includes Keycloak; V7 backfills existing documents and indexing jobs into the legacy workspace. Browser login, Bearer JWT API access, private personal workspaces, member sharing, and workspace-scoped retrieval/indexing are covered by tests. Do not apply V7 to the deployed database until an explicit migration/deployment is approved.
- The document review gate is implemented locally in V12 but has not been applied to the VM. New indexing requests, including the legacy `POST /api/documents/s3` route, now scan uploaded bytes with the private Compose ClamAV service before extraction, then return exact quoted evidence, validated line/page locations, indicator categories, and uncertainty/missing context; no fraud/safety verdict is returned. Workspace-owner approval remains required before indexing. The UI system map shows the ClamAV scan, extraction/transcription, evidence-screening model, and approval gate. Malware detections, scanner outages, and offline AI screening fail closed. Do not apply V12 or deploy without explicit approval.
- The `/files` page shell is public so signed-out users can see a sign-in prompt; its file data remains behind authenticated, workspace-scoped APIs. Its sign-in action returns users to `/files` after Keycloak login. The page lists uploaded files for the selected workspace and shows each file's latest indexing status, stage, and failure message. Status data refreshes while jobs are active. This change is local and has not been deployed.
- Provider-operation hardening is implemented locally: Infomaniak calls have configurable request/connect/read timeouts, one default retry, a shared per-process fail-fast concurrency limit, and Micrometer latency/error/rejection metrics. Whisper has an overall configurable deadline and dynamically caps each request timeout to its remaining budget. The bounded indexing executor reports active/queued/capacity metrics; rejected enqueue requests are marked failed and return 503. Persisted queued jobs rejected during startup recovery remain queued and are retried periodically in bounded batches that exclude already-dispatched IDs; synchronized dispatch reservations prevent API/recovery races. `/actuator/metrics` is exposed but remains subject to authentication. No deployment was performed.
- RAG query caching uses private Redis as a shared L2 cache with bounded in-process L1 caches. Embeddings are keyed by model and search text; verified answers are keyed by workspace, effective question/profile, and ordered source citations. Retrieval/reranking remain fresh on every request. Local capacity (`RAG_CACHE_MAX_ENTRIES`), expiry (`RAG_CACHE_TTL_SECONDS`), Redis memory (`RAG_CACHE_REDIS_MAX_MEMORY`), timeouts, and Micrometer hit/miss/eviction/error metrics are configured. Redis is ephemeral and not published to the host; failures are logged and counted while the request continues through normal RAG behavior. Provider-managed prompt caching remains opportunistic because no documented Infomaniak API toggle was established. No deployment was performed.
- Ollama context size is configurable with `RAG_OLLAMA_CONTEXT_TOKENS` (default 32,768; accepted range 1,024–131,072), applied to local chat/planner/screening/grounding requests, and displayed in the authenticated Models in use UI. Unit/config tests pass. A Playwright browser E2E and CI job verify the configured 65,536-token value without making model inference calls; CI will run it on pushes and pull requests.
- Local Ollama mode can use the Hugging Face `paulalesius/Qwen3-Reranker-0.6B-GGUF` Q6_K model through a private llama.cpp Compose service by setting `RAG_OLLAMA_RERANK_PROVIDER=llamacpp` and enabling `COMPOSE_PROFILES=llama-reranker`. The reranker service downloads the GGUF on first startup and caches it in a named volume. The local service successfully loaded the model and ranked a synthetic two-passage query; its healthcheck uses port 8081. The current local `.env` selects this provider. No VM deployment or workload-quality/parallel-capacity evaluation was performed.
- Local document escalation now scans source bytes with ClamAV, extracts embedded PDF text first, and uses bounded Tesseract OCR for sparse PDF pages and PNG/JPEG uploads. Low-confidence OCR can fall back to local Ollama Gemma vision, followed by a separate check against the original page/image. Stages are persisted as OCR, VISUAL_ANALYSIS, and ORIGINAL_REVIEW; Flyway V14 adds the database constraint values. The VM's Infomaniak vision API path is intentionally not implemented or deployed. An optional OpenAI-compatible local vLLM client is available by explicit configuration, but no vLLM server is installed on the Apple Silicon laptop; the tested local path is Ollama/Gemma. Owner approval is still required before indexing.
- `POST /api/documents/s3` reads UTF-8 text, extracts PDF text, and locally OCRs low-text PDF pages and uploaded PNG/JPEG images before placing the result in the review workflow; approved content is indexed into PostgreSQL and original files stay in RustFS.
- `RAG_EMBEDDING_DIMENSIONS` drives the Flyway vector column and both online/offline embeddings. It must match the embedding model output and be at most 2000 for the HNSW index.
- The previous baseline passed `./mvnw test` with Java 27, including pgvector integration and S3 ingestion coverage. The uncommitted review-gate change has not yet been compiled or tested because the sandbox blocked execution of the Maven wrapper. Compose YAML parsed successfully; the deployed API and storage health checks pass.
- No live AI provider call, Kubernetes deployment, commit or push was performed. The existing `.gitignore` is preserved; `pck-odnd2cl-kubeconfig` remains ignored and must not be read.
- Local deployment verification (2026-11-25): the Compose app and Keycloak are running on loopback; V7 is applied to the local database. 69 Maven tests passed, and live OIDC login, admin-role mapping, workspace access, CSRF, workspace isolation, and logout passed. No Infomaniak inference was triggered. The existing VM was not changed.
