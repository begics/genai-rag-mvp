# GenAI RAG MVP

This is a single Spring Boot 4.2 application with PostgreSQL/pgvector. It ingests text, PDFs, and supported audio/video files from RustFS, retrieves stored chunks with hybrid PostgreSQL full-text and pgvector search, and returns answers with source passages. Infomaniak AI Services provides chat, embeddings, reranking, and Whisper transcription through its APIs.

## IntelliJ and local startup

Each user has a 1 GB (1,000,000,000-byte) S3 object quota and a separate 1 GB indexed-data quota, aggregated across all owned workspaces. The UI shows both totals and lets users delete stored files (including their index) or index/re-index supported files. Indexed-data usage counts persisted chunk text, embeddings, and full-text search vectors; it does not include PostgreSQL table, WAL, or vector-index overhead.

Copy `.env.example` to `.env` and replace the placeholder credentials and AI service settings. Run `docker compose up -d` to start the application, Keycloak, PostgreSQL, and RustFS. The long-running services use Docker's `unless-stopped` restart policy, so they restart after Docker or the host restarts unless explicitly stopped. On a Linux VM, also enable the Docker daemon at boot (for example, `sudo systemctl enable --now docker`). Open `http://localhost:8080/`; the app redirects to Keycloak at `http://localhost:8180` for sign-in. Keycloak self-registration is enabled for local development. Compose seeds a `ROLE_ADMIN` account in the `rag` realm using `KEYCLOAK_ADMIN_USERNAME` (default `admin`), `KEYCLOAK_ADMIN_PASSWORD`, `KEYCLOAK_ADMIN_EMAIL`, `KEYCLOAK_ADMIN_FIRST_NAME`, and `KEYCLOAK_ADMIN_LAST_NAME`; use the configured username and password to sign in to the app and Keycloak's admin console. The realm admin account is created on first startup and is not reset when its password is changed later. Do not expose the development Keycloak port publicly.

Set your Infomaniak AI Services API token, product ID, available chat model ID, embedding model, and reranker in `.env`. The selected BGE Multilingual Gemma2 embedding model uses 3,584 dimensions. Chunks store these embeddings as `halfvec(3584)` with the model ID recorded per chunk; retrieval excludes vectors produced by other models. Search combines PostgreSQL full-text and vector results, then reranks up to 20 candidates with the Cohere-compatible reranking endpoint. Infomaniak documents `GET /1/ai` to find the product ID and `GET /2/ai/{product_id}/openai/v1/models` to list chat and embedding models, plus `/2/ai/{product_id}/cohere/v1/models` to list rerankers.

With `RAG_PROVIDER=infomaniak`, agent planning uses the separately configurable `INFOMANIAK_AI_AGENT_PLANNER_MODEL` (default `google/gemma-4-31B-it`); answer generation and invoice extraction continue using `INFOMANIAK_AI_CHAT_MODEL`. The planner model must be available to the AI product and support JSON Schema structured output. Change the planner model independently if needed; the application does not silently fall back to the answer model if planning fails.

The GitHub Actions `CI` workflow runs the Maven suite and image build for every push and pull request. On pushes to `main`, it also runs a visible-flow-equivalent, headless browser E2E against a fresh local Compose stack using real Infomaniak models; it uploads and indexes only a synthetic test document, verifies a cited model answer, then deletes the test file and index. Configure repository Actions secrets `AGENT_E2E_USERNAME`, `AGENT_E2E_PASSWORD`, `INFOMANIAK_AI_API_KEY`, `INFOMANIAK_AI_PRODUCT_ID`, `INFOMANIAK_AI_CHAT_MODEL`, `INFOMANIAK_AI_EMBEDDING_MODEL`, `INFOMANIAK_AI_RERANK_MODEL`, and `RAG_EMBEDDING_DIMENSIONS`; `INFOMANIAK_AI_AGENT_PLANNER_MODEL` is optional and defaults to Gemma 4 31B IT. The live test makes billable provider calls and runs only on trusted `main` pushes or manual dispatches on `main`; credentials are not exposed to pull-request code. Set `CI / verify` as a required branch-protection check to gate pull-request merges. You can manually run the full workflow from the Actions tab on `main`.

Uploads are limited to 20 MiB per file, including text, PDFs, and media. With `RAG_PROVIDER=infomaniak`, supported audio/video uploads (AAC, FLAC, M4A, MP3, MP4, OGG/Opus, WAV, WebM, and WMA) can be indexed: only after the user chooses **Index for chat**, the background job sends the file to Infomaniak's asynchronous Whisper transcription endpoint, polls its batch status, downloads the plain-text transcript, and indexes that text for chat. Your Infomaniak AI product may impose a lower media size limit. Transcription can incur provider usage. If the application restarts during transcription, that job is marked failed rather than automatically resubmitting the media; choose **Re-index** to retry. No live transcription request is made by automated tests. In offline mode, media can still be stored but cannot be indexed. MOV/M4V are not accepted because they are unsupported by the transcription flow.

The local model provider defaults to `offline` when no `.env` is loaded, so automated tests need no credentials or provider calls. Its hash-based embeddings, pass-through reranker, and canned chat response are a smoke-test fallback, not semantic retrieval. With the example `.env` configured, `RAG_PROVIDER=infomaniak` selects Infomaniak for chat, embeddings, and reranking.

After signing in, each user receives a private personal workspace. Create additional private workspaces in the UI; workspaces are accessible only to their owner. Indexed documents are listed persistently for the selected workspace, including each document’s indexed chunk count. All document retrieval, embedding reindexing, uploads, and job status lookups are scoped to the selected workspace. The UI handles browser session security and CSRF automatically. API clients can authenticate with Keycloak-issued Bearer access tokens and select a workspace with `X-Workspace-ID`; workspace ownership is checked on every request.

The API accepts OIDC login sessions for the browser and JWT Bearer tokens for API clients; Basic authentication is not enabled. Keycloak maps realm roles to Spring authorities (`USER` and `ADMIN`), while PostgreSQL workspace membership remains the authorization source for tenant data. Admins use their personal workspace by default, like other users. Security protections include a same-site CSRF cookie/token for browser POST requests, a restrictive Content Security Policy, anti-framing and MIME-sniffing headers, and rate limits. Uploads are checked against file signatures or strict UTF-8 before being written to object storage; the supplied MIME type is not trusted. The in-memory rate limiter is intended for this single-instance deployment. Compose ports bind to loopback; before exposing the service, configure TLS at a trusted reverse proxy, restrict proxy access to the app, and configure Keycloak's hostname, redirect URIs, and secrets for that deployment.

For non-browser API use, obtain a Keycloak access token through an OAuth2 Authorization Code + PKCE flow (direct password grants are disabled), and set `ACCESS_TOKEN` and `WORKSPACE_ID` to the token and an assigned workspace UUID. Uploads must use a workspace-prefixed S3 key such as `uploads/$WORKSPACE_ID/notes/notes.pdf`. Then enqueue background indexing with `POST /api/indexing-jobs/s3` (the bucket comes from `S3_BUCKET`):

```json
{"key":"uploads/$WORKSPACE_ID/notes/notes.pdf"}
```

The endpoint returns `202 Accepted` and a job ID. Check progress with `GET /api/indexing-jobs/{id}`; completed jobs include the indexed chunk count, while failed jobs expose an error message. Jobs are persisted in PostgreSQL, resumed after an app restart, and use the job ID as an idempotency key so recovery does not duplicate documents. The worker accepts UTF-8 text, PDFs with extractable text, and supported media when Infomaniak is configured; scanned/image-only PDFs require OCR and are not supported.

The UI prioritizes asking questions and managing knowledge; its technical file-indexing and answer-generation flows are available in a collapsible overview. After sign-in it displays the configured provider and model IDs; recent workspace jobs show their persisted stage and final result, refreshing every three seconds while work is active. The demo and private workspace adapt to mobile screens, with touch-sized controls and safe-area spacing for iPhone.

The demo and private UI explain Cloudflare Workers AI extraction models as a separate pattern for returning typed fields, computing values from supplied facts, and estimating or forecasting outcomes. This application does not currently call those models: its document workflow extracts text, indexes passages, retrieves evidence, and generates answers with the configured provider. Typed output and constraints are not correctness guarantees; validate extracted values against source evidence, especially before consequential actions. See the [Cloudflare extraction models documentation](https://developers.cloudflare.com/workers-ai/concepts/extraction-models/).

The private UI also offers optional invoice-field extraction for stored text, Markdown, CSV, and readable PDF files. It returns supplier, invoice number, invoice/due dates, currency, and total together with a source quotation for each non-null value. Extraction uses the configured Infomaniak chat model with strict JSON Schema output and does not change the RAG index; the selected model must support JSON Schema output. Offline mode reports that the feature is unavailable. Each document is limited to 100,000 extracted characters. The API endpoint is `POST /api/documents/extract-invoice` with `{"key":"uploads/<workspace-id>/<file>"}` and the usual authenticated workspace context. Provider output is still validated for fields, types, dates, decimal values, and quoted evidence. Review results before using them; this is not accounting advice or an approval workflow.

The private UI also supports workspace-scoped folder uploads, opening the indexed passage for a retrieved quotation, and comparing two stored text, Markdown, CSV, or readable PDF files. Source context is read from the workspace-scoped index, so opening a transcript does not submit its media for transcription again. Folder structure below the selected root is retained in object keys. Document comparison reports exact added and removed paragraphs; it is not a semantic or line-by-line diff, and files must contain extractable text. The chat UI offers general, support, procedure, and summary answer profiles; profiles guide answer phrasing but do not alter retrieval or guarantee correctness. Invoice extraction flags an earlier due date or a missing total/currency pair for review, but it does not reconcile tax or line-item arithmetic. Answer feedback is summarized within the active workspace as helpful/not-helpful submissions; this user sentiment is not a measure of factual accuracy.

Agentic research is enabled by default in the private chat UI. With Infomaniak, the planner uses the separately configurable Gemma 4 31B IT model by default and structured output to select up to three focused searches or request an exact comparison of two indexed text, Markdown, CSV, or PDF documents; final answers continue using the configured chat model. Planner JSON is checked server-side for exactly the required fields, valid JSON types and bounds; duplicate fields, trailing values, unknown/missing fields, and malformed JSON are rejected. The backend verifies comparison IDs refer to two different, indexed, comparable documents in the active workspace before invoking any search or comparison; invalid plans fail with `502 Bad Gateway`. It receives metadata for at most 100 indexed documents in the active workspace. Search results are deduplicated and reranked against the original question; the answer includes the normal source passages and a visible trace of planning, tools, comparison, and answering. This first agent is read-only: it cannot modify/delete documents, run SQL, or trigger invoice extraction/transcription. The run is bounded to one planning call, at most three searches, one optional comparison, and one answer. In offline mode, planning uses a deterministic one-query plan and makes no model-provider calls. The UI leaves the indexing, RAG, and configured-component explanations expanded and shows the latest agent run status. The authenticated endpoint is `POST /api/agent/query` with the same `question`, `source`, `documentType`, and `assistantMode` fields as `POST /api/query`; it returns `answer`, `sources`, `steps`, optional `comparison`, and `maxSteps`. Structured planner failures are surfaced rather than silently replaced by an unsafe fallback.

The public demo is a self-contained showcase with fictional documents and prepared example answers matched by keywords; it makes no API or model-provider calls, stores nothing, and is separate from authenticated workspaces. Point the Cloudflare Tunnel public hostname `ai-demo.begic.ch` to `http://app:8080`; its root URL `https://ai-demo.begic.ch/` serves the demo directly. The private application remains at `https://ai-rag.begic.ch/` and continues to require sign-in for workspace APIs.

Alternatively, enqueue text directly with `POST /api/indexing-jobs`:

```json
{"source":"notes.txt","text":"PostgreSQL stores relational data and supports extensions."}
```

For API requests, send the bearer token and workspace header. Browser clients using the OIDC session instead must preserve the `XSRF-TOKEN` cookie and send its value in `X-XSRF-TOKEN` for state-changing requests; the built-in UI does this automatically.

```sh
curl -H "Authorization: Bearer $ACCESS_TOKEN" -H "X-Workspace-ID: $WORKSPACE_ID" \
  -H 'Content-Type: application/json' \
  -d '{"source":"notes.txt","text":"PostgreSQL stores relational data and supports extensions."}' \
  http://localhost:8080/api/indexing-jobs
```

Text is split at paragraph boundaries with a 1,500-character ceiling and a 200-character overlap. Very long paragraphs split at word boundaries where possible. Embeddings are sent in batches of at most 100 chunks per provider request. This character-based limit is a tokenizer-independent approximation, not a model token limit.

Query with `POST /api/query`: `{"question":"What stores relational data?"}`. PostgreSQL full-text search (`simple` configuration and GIN index) retrieves exact terms, while pgvector retrieves semantically similar chunks; reciprocal rank fusion combines their rankings, then Infomaniak reranks the candidates before the chat model receives context. To generate embeddings for chunks whose recorded model differs from the active model, call the authenticated endpoint:

```sh
curl -X POST -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "X-Workspace-ID: $WORKSPACE_ID" \
  http://localhost:8080/api/documents/reindex-embeddings
```

The response contains a job ID; poll `GET /api/indexing-jobs/{id}` with the same Bearer and workspace headers until `COMPLETED` or `FAILED`. Reindex jobs only process chunks in the selected workspace with missing or stale model versions and are safe to retry. Requests are validated; blank and oversized input is rejected.

Run tests with `./mvnw test`. ArchUnit enforces package dependency boundaries and cycle-free slices. PostgreSQL integration tests use a disposable Testcontainer and are skipped when Docker is unavailable. The small deterministic retrieval evaluation corpus is in `src/test/resources/retrieval-evaluation.json`; its integration test checks Recall@5 ≥ 1.0 and MRR ≥ 0.75. It exercises lexical and vector retrieval only, not live model answer quality.

For a live end-to-end evaluation against the local Infomaniak-backed app, run `npm ci` once and then `npm run eval:rag:live`. The runner requires the local Compose services to be running and `RAG_PROVIDER=infomaniak` with the Keycloak and Infomaniak settings configured in `.env`. Promptfoo tests two synthetic facts for answer and source attribution, plus a question that must not be answerable from the test corpus. The runner creates a temporary workspace and removes its jobs and documents afterward, including when evaluation fails. Live model calls may incur provider usage; no project documents are sent.

To evaluate agent planning specifically, run `npm run eval:agent:live` with the same local setup. It uses synthetic facts and two synthetic policy versions in a temporary workspace, then checks answer/source grounding, abstention when evidence is absent, avoiding an unnecessary comparison, and comparing the requested documents with the expected changed paragraphs. Comparison documents are uploaded and indexed through the S3 workflow because the comparison tool reads the originals; the runner removes those objects and temporary workspace records afterward. Six additional observatory QA cases were generated with Meta's [Synthetic Data Kit](https://github.com/meta-llama/synthetic-data-kit) from `promptfoo/fixtures/synthetic-planner-seed.txt`, manually checked against that fictional source, and included in the live evaluation. See `promptfoo/fixtures/synthetic-planner-qa.json` for the expected facts. This kit is useful for generating varied, source-grounded QA tests, but it does not generate gold planner search queries or tool decisions, so it does not directly create planner SFT labels. These cases are held-out quality checks, not training data. Infomaniak-hosted model weights are not available for LoRA fine-tuning; any future SFT/GRPO experiment needs a compatible open-weight model on separate GPU infrastructure and human-verified synthetic planner examples. Helpful/not-helpful feedback alone is not a correctness reward.

To also evaluate against a small, selected HSLU repository sample, run `HSLU_REPO_PATH=/path/to/cas-llms-and-ai-agents-hs-2026 npm run eval:rag:hslu`. This separate live evaluation reads only the tracked `wiki/rag-course-architecture.md` file from that checkout; it does not ingest the whole repository, PDFs, notebooks, local/untracked files, or credentials. The file is sent to the configured Infomaniak services for indexing and answer generation. Confirm that this use is permitted for the course material before running it. Results are not shared or written to Promptfoo's local result store, and the temporary workspace is removed afterward.

## Kubernetes preparation

Review `deploy/k8s/` and customize the image, storage class, resource limits, product/model IDs, embedding dimension, external S3 endpoint, Keycloak issuer/endpoints, client redirect URI, and secret values for the target operator. Configure a reachable Keycloak realm; the sample manifests do not deploy an identity provider. PostgreSQL is a ClusterIP service with an explicit PVC and health probes. `secret.example.yaml` contains placeholders only; replace them before applying any resources. The Dockerfile builds the application image with JDK 27. These manifests are preparation artifacts: this repository never applies them or accesses a cluster.

Local RustFS stores original files; the application reads UTF-8 text and extracts text from PDFs, then stores chunks and embeddings in PostgreSQL. OCR for scanned PDFs, other binary formats, workers, ingress/DNS/TLS and backup automation are intentionally deferred from this MVP. Configure TLS at the ingress or reverse proxy before exposing the API beyond a trusted private network.

The Compose stack also includes Portainer CE at `https://localhost:9443` for Docker management. Its port is bound to loopback; connect to the VM through SSH port forwarding rather than exposing the UI publicly. Portainer has access to the Docker socket and therefore effectively has host-level control.

To use Cloudflare Tunnel, create a remotely managed tunnel in Cloudflare Zero Trust and add its token as `CLOUDFLARED_TUNNEL_TOKEN` in `.env`. Configure public hostnames `ai-rag.begic.ch` and `ai-demo.begic.ch` → `http://app:8080`, and `auth.begic.ch` → `http://keycloak:8080` in the tunnel dashboard, then start the tunnel with `docker compose --profile cloudflare-tunnel up -d cloudflared`. This creates the profile-enabled connector with an `unless-stopped` restart policy; Docker will restart it on host boot along with the app, Keycloak, PostgreSQL, and RustFS. The Docker daemon itself must be enabled at boot, and the tunnel must have been started once with this profile. The cloudflared container joins the Compose network and makes outbound connections only; it does not publish ports.

On the Ubuntu VM, install UFW and the persistent host-firewall service with `sudo ./deploy/ufw/install.sh` from this checkout. It denies unsolicited inbound and routed traffic, allows outbound traffic, and permits SSH only from the Compose Docker bridge used by the Cloudflare connector. The systemd unit recalculates the bridge interface and subnet after Docker starts, including after Docker restarts. Keep `sshd` running for the tunnel, but do not open public port 22. Review the script and confirm the Compose network name (`genai-rag_default`) before using a different project name. UFW complements, rather than replaces, the Infomaniak/OpenStack ingress firewall.
